# 백엔드 도메인 책임과 UI 계약 명세

2026-11-08 사용자 확정 · 실행 구현 없음.

비즈니스 규칙은 백엔드 도메인이 소유한다. 애플리케이션 레이어는 도메인 호출·트랜잭션·입출력 조정을 맡고, UI는 서버가 반환한 기본값·권한·처리 결과·버전을 표시한다. 이 저장소에서는 해당 규칙을 구현하는 모의 도메인/동기화 엔진도 추가하지 않는다.

## 레이어별 책임

| 주제 | 백엔드 도메인 | 애플리케이션·인프라·UI |
| --- | --- | --- |
| 담당자 | 미정 허용, 생성자 기본 배정, 최대 한 명 | UI는 서버 초안의 기본값을 표시. 생략/명시적 미정의 입력 계약 전달 |
| 변경·이동 | 참여자의 변경 권한과 언제든 소속 이동 가능 원칙 | 애플리케이션은 인증 주체·대상·명령을 도메인에 전달. UI는 반환된 허용 동작과 결과 표시 |
| 삭제·복구 | 스페이스 관리자 권한 판단과 정책 | UI 버튼 상태로 보안을 대신하지 않음. 서버가 모든 요청을 검증 |
| 초대 | 팀 스페이스 초대, 1시간 유효성·취소·참여 결과 | Redis 어댑터가 도메인 만료 시각에 맞춰 TTL 3600초 저장. 클라이언트 시각으로 수락 승인하지 않음 |
| 중복 참여 | 회원 ID 기준 중복 방지와 멱등 결과 | 저장소에서 스페이스 ID+회원 ID 유일성과 원자성을 보장. 닉네임은 가입 프로필의 표시 데이터 |
| 동시 수정 | 충돌의 의미와 저장 실패 결과 | 저장소의 원자적 조건부 갱신으로 낙관적 락 보장. 애플리케이션은 임의 덮어쓰기/재시도 없이 결과 전달 |
| 실시간 갱신 | 공유 가능한 변경·대상·권한 정의 | 저장 후 이벤트·실시간 전송 어댑터로 전달. UI는 최신 상태 표시 |
| 프로젝트 분류 | 카테고리 대체 관계와 데이터 이전 정책 | UI·검색·통계가 서버의 같은 프로젝트 소속을 소비 |

Redis·DB·이벤트 전송은 포트/어댑터로 연결한다. 기술 입출력 실패의 처리와 트랜잭션 조정은 애플리케이션 책임이지만, 권한·만료·담당자·중복·이동 같은 업무 판단을 애플리케이션으로 옮기지 않는다.

## 계약에 포함할 정보

- 생성 초안의 기본 담당자와 가입 프로필 닉네임.
- 서버가 판단한 수정·담당자 변경·이동·삭제·복구·초대 관련 allowed actions.
- 서버 발급 초대 링크, 만료 시각, 검증 가능한 초대 상태.
- 저장 시 전달할 항목 버전과 서버가 반환하는 최신 버전·최신 상태.
- 가입 성공/이미 참여/유효하지 않거나 만료/취소/삭제된 스페이스/로그인 필요/일시 실패/편집 충돌 등의 결과 구분.

이는 개념 수준의 계약 명세다. 실제 API 경로·DTO·DB 테이블·Redis 키 구조·실시간 전송 방식을 확정하거나 구현한 상태가 아니다.

## 백엔드 수용 조건

1. 담당자 입력 생략 시 생성자를 기본 배정하고, 명시적 미정은 허용한다.
2. 일반 참여자는 내용·담당자·소속을 변경할 수 있고 관리자만 삭제·복구한다. 권한 검증은 직접 API 호출에도 적용된다.
3. 기본 본인 전용 공간은 초대를 허용하지 않는다. 팀과 스페이스를 별도 재사용 팀 모델로 분리하지 않는다.
4. 초대는 서버에서 발급하고 Redis에 1시간 만료로 저장한다. 서버 시각과 도메인 유효성 규칙으로 수락 시 재검증한다.
5. 같은 회원의 연속·동시 참여나 재시도로 멤버가 중복 생성되지 않는다. 동일 닉네임을 동일 회원으로 판정하지 않는다.
6. 만료 경계·키 소멸·취소·스페이스 삭제·수락 경쟁·저장 실패를 다룬다. 사라진 Redis 키의 원인을 알 수 없을 때 클라이언트가 임의로 구분하지 않는다.
7. 저장소에 반영되지 않은 참여를 성공으로 응답하지 않는다. 재시도는 멱등적으로 처리한다.
8. 낙관적 락의 버전 불일치는 기존 변경을 덮어쓰지 않고 실패 결과와 최신 상태로 전달한다.
9. 승인된 변경은 권한 있는 참여자에게 실시간 전달한다. 접근 대상 판단도 서버에서 한다.
10. 기존 카테고리 데이터의 프로젝트 전환 상세는 별도 이전 명세로 검토하며 UI가 임의 변환하지 않는다.

## UX와 구현의 구분

UI의 버튼 비활성화·처리 중 표시·주의 문구·입력 임시 보관은 표시와 사용성의 책임이다. UI가 업무 규칙을 독자 구현하거나 서버 응답 없이 성공·권한·만료를 확정하지 않는다.

이번 디자인 작업은 명세만 남긴다. 실제 백엔드·운영 코드와 Redis·DB를 변경하지 않았다. 작성 중 추가했던 실행용 모의 도메인/정책/동기화 코드와 테스트는 철회했다. 기존 승인 시안의 실행 소스를 복원했으며 문서 전용 변경으로 검토한다.
