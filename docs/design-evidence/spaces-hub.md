# 핀잇 스페이스 허브

2026-11-09 · 디자인 시안 0.18.0 · 기준 브랜치 `codex/personal-first-spaces-design-20261108`(`5ac921f`)에서 분기.

예시 데이터로 실행하는 시안이다. 제품 API·권한·초대 만료·멤버십을 구현하거나 검증하지 않는다.

## 출발점

[pinit-docs](https://github.com/Pinit-Scheduler/pinit-docs)의 공통 시작점과 FE `pinit-fe@4f2942c`, BE `pinit-monolith@a806512d` 계약, 이 저장소의 0.16–0.17 시안을 페이지별로 대조했다. 공통 문제는 다음과 같았다.

- 팀·프로젝트의 현재 상태(진행, 누가 무엇을 맡았는지, 담당자 미정 작업)를 볼 곳이 없다.
- 관리 화면이 선택한 스페이스 하나만 보여 주고, 스페이스를 바꾸려면 다른 화면을 거쳐야 한다.
- 관리 진입점이 여러 곳에 흩어져 있고 이름이 다르다.
- 역할·관리자·불가 사유가 보이지 않는다.
- 소속 표시와 실행 버튼이 같은 파랑을 쓴다.

## 사용자 확정 사항 (2026-11-09)

| 항목 | 확정 내용 |
| --- | --- |
| 개관 화면 | 관리 화면을 스페이스 개관(허브)으로 바꾼다. 왼쪽에 모든 스페이스, 오른쪽에 선택한 스페이스의 목적·프로젝트 진행·참여자별 담당·담당자 미정 작업, 설정은 아래로 둔다. 이전 시안의 "새 대시보드를 만들지 않는다" 제약을 이 범위에서 해제한다. |
| 전환 후 위치 | 스페이스나 프로젝트를 바꿔도 보던 화면에 머문다. |
| 개인 스페이스 | 팀 스페이스와 같은 구조를 쓰고 참여자·담당 영역만 숨긴다. |

## 디자인 계획 (승인본)

- 색: 기존 #F4F6FA·#FFFFFF·#202A3C·#727C8D·#345CE5·#EDF2FF 유지. 파랑은 실행과 선택에만 쓴다. 스페이스 정체성은 작업 맵 카테고리 색(#3e8391, #9165b0, #a77d35, #43886b, #ad6280)에서 하나씩 배정한 작은 표시로 나타낸다. 파랑에 가까운 #4b70c2는 제외했다. 개인 스페이스는 무채색 테두리다.
- 글꼴: Noto Sans KR 하나. 목적 문장만 32px(모바일 24px)·굵기 400으로 크게 쓴다. 나머지는 15px 이하. 목적 위에 라벨을 달지 않는다. 숫자는 tabular-nums.
- 배치: 스페이스 목록(232px) + 개관 한 장. 프로젝트와 담당은 카드가 아니라 행 목록이고, 행 동작은 `⋯` 메뉴에 넣는다. 1600px 이상에서 프로젝트와 담당을 나란히 둔다. 760px 이하에서는 목록 → 상세(뒤로 버튼)로 나눈다.
- 원칙: 목적이 주인공이다. 숫자는 셀 수 있는 사실(완료 n/m, 미정 n)만 보여 주고 진행률 %·점수를 만들지 않는다. 권한이 없는 동작은 이유를 한 줄로 알린다. 동작 이름은 하나로 쓴다.
- 기본값과 비교해 고친 점: 진행 막대 대신 작업 하나를 점 하나로 그린다(담당자 미정이 프로젝트 안에서 보이도록). 아바타 묶음 대신 이름과 역할을 글로 쓴다. 상단 숫자 칸 줄을 두지 않는다.

## 변경 파일

- `purpose-spaces-hub.js` / `.css`: 허브 화면, 예시 데이터 정렬, 브레드크럼 범위, 관리 모달 대체, 링크 초대 안내, 담당자 미정 표시.

## 예시 데이터와 경계

- 이 시안의 가능 여부·불가 사유는 스페이스마다 `exampleActions`로 적어 둔 정적 값이다. 서버 `allowedActions`를 대신해 화면 상태를 보여 줄 뿐이며 역할로부터 권한을 계산하지 않는다. 시안에서 새로 만든 스페이스는 만든 사람을 관리자로 적어 둔다.
- 추가한 예시: "핀잇 개선"에 민지·준호와 프로젝트 "온보딩 안내 정리", 내가 일반 참여자인 "주말 러닝 모임"(관리자 서연), 예시 작업 101–109. 담당자 미정은 `none`으로 기록한다. 이 때문에 오늘에 내 담당 예시 작업 108이 추가로 나온다. 다른 사람이 맡은 작업과 담당자 미정 작업은 오늘에 나오지 않는다.
- 초대 링크는 `/spaces/join/example-link` 예시 문자열이다. 만료·재사용·철회는 서버가 판정한다는 안내만 보여 준다.
- 진행 중(◐) 점은 연결 일정이 진행 중·일시정지일 때만 나온다. 이 상태의 예시는 넣지 않았다.

## 제안 및 미결 사항

- 제안: 사이드바에서 "스페이스" 위치(오늘 바로 다음), 스페이스 표시 색 배정 방식, 점 표시를 막대로 바꾸는 기준(20개), 모바일 진입을 하단 메뉴 대신 스페이스 시트의 "모든 스페이스 보기"로 둔 것.
- 미결: 허브 숫자의 출처(FE 집계 vs BE 요약 — 미완료·진행 정의는 BE 도메인 소유가 적절), 팀 스페이스의 일정·통계 기본 범위, 담당자 필터·배정자 정보 등 BE 계약 확장, 오늘에서 만든 작업의 기본 위치, 활성 초대 링크를 다시 보는 곳, 프로젝트 공간 이동 메뉴.
- 범위 밖: 작업·일정 폼, 오늘, 일정·통계 등 다른 화면의 분석 결과는 이번에 바꾸지 않았다. 작업 카드의 프로젝트 경로와 카테고리 중복 표시도 그대로다.
