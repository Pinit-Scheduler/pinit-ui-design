# 핀잇 스페이스 허브

2026-11-09 · 디자인 시안 0.18.0 · 기준 브랜치 `codex/personal-first-spaces-design-20261108`(`5ac921f`)에서 분기.

예시 데이터로 실행하는 시안이다. 제품 API·권한·초대 만료·멤버십을 구현하거나 검증하지 않는다.

## 출발점

[pinit-docs](https://github.com/Pinit-Scheduler/pinit-docs)의 공통 시작점과 FE `pinit-fe@4f2942c`, BE `pinit-monolith@a806512d` 계약, 이 저장소의 0.16–0.17 시안을 페이지별로 대조했다. 공통 문제는 다음과 같았다.

- 팀·프로젝트의 현재 상태(진행, 누가 무엇을 맡았는지, 담당자 미정 작업)를 볼 곳이 없다.
- 관리 화면이 선택한 스페이스 하나만 보여 주고, 스페이스를 바꾸려면 다른 화면을 거쳐야 한다.
- 관리 진입점이 여러 곳에 흩어져 있고 이름이 다르다.
- 역할·관리자·불가 사유가 보이지 않는다.
- 소속 표시와 실행 버튼이 같은 파랑을 쓴다.

## 사용자 확정 사항 (2026-11-09)

| 항목 | 확정 내용 |
| --- | --- |
| 개관 화면 | 관리 화면을 스페이스 개관(허브)으로 바꾼다. 왼쪽에 모든 스페이스, 오른쪽에 선택한 스페이스의 목적·프로젝트 진행·참여자별 담당·담당자 미정 작업, 설정은 아래로 둔다. 이전 시안의 "새 대시보드를 만들지 않는다" 제약을 이 범위에서 해제한다. |
| 전환 후 위치 | 스페이스나 프로젝트를 바꿔도 보던 화면에 머문다. |
| 개인 스페이스 | 팀 스페이스와 같은 구조를 쓰고 참여자·담당 영역만 숨긴다. |
| 명칭 | 화면 용어 "공간"을 "스페이스"로 바꾼다. |
| 시안 계획 | 아래 디자인 계획을 승인했다. |
| 허브 숫자 출처 | BE가 스페이스별 요약(프로젝트별 완료 n/m, 참여자별 미완료, 담당자 미정 수, 스페이스별 미완료)을 내려 준다. 미완료·진행 중의 정의는 BE 도메인이 소유하고 FE는 집계하지 않는다. BE 계약 추가가 필요하다. |
| 팀 스페이스 일정 | 기본은 내 담당 일정만 보여 준다. "팀 전체 보기"를 켜면 팀원 일정이 담당자 이름과 함께 나온다. |
| 팀 스페이스 통계 | (아래 "통계 분리"로 대체됨) 처음에는 통계 화면에서 참여자 전원 합계를 집계하고 범위를 명시하기로 했다. 0.19.0 시안이 이 결정을 그렸다. |
| 통계 분리 | 통계 메뉴는 항상 "내 통계"다. 선택한 스페이스와 관계없이 모든 스페이스의 내 기록을 보여 주고, 스페이스·프로젝트별로 나눠 볼 수 있다. 팀 통계는 스페이스 허브에 둔다. |
| 시간 지표 공유 | 집중 시간·투자한 시간은 제한 없이 공유한다. 팀 통계에 사람별 시간까지 보여 줄 수 있다. (한때 "시간은 개인용, 팀에는 시간 없음"으로 답했다가 같은 대화에서 "공유도 허용, 제한 없이"로 바꿨다.) |
| 내 기록의 기준 | 일정의 "내 기록"과 사람별 시간은 실제로 실행한 사람 기준으로 센다. |
| 오늘에서 만든 작업 | 기본 위치는 나의 스페이스다. 폼에서 바꿀 수 있다. 이 시안은 이미 이렇게 동작하고, FE는 선택된 스페이스에 넣으므로 바꿔야 한다. |

## 디자인 계획 (승인본)

- 색: 기존 #F4F6FA·#FFFFFF·#202A3C·#727C8D·#345CE5·#EDF2FF 유지. 파랑은 실행과 선택에만 쓴다. 스페이스 정체성은 작업 맵 카테고리 색(#3e8391, #9165b0, #a77d35, #43886b, #ad6280)에서 하나씩 배정한 작은 표시로 나타낸다. 파랑에 가까운 #4b70c2는 제외했다. 개인 스페이스는 무채색 테두리다.
- 글꼴: Noto Sans KR 하나. 목적 문장만 32px(모바일 24px)·굵기 400으로 크게 쓴다. 나머지는 15px 이하. 목적 위에 라벨을 달지 않는다. 숫자는 tabular-nums.
- 배치: 스페이스 목록(232px) + 개관 한 장. 프로젝트와 담당은 카드가 아니라 행 목록이고, 행 동작은 `⋯` 메뉴에 넣는다. 1600px 이상에서 프로젝트와 담당을 나란히 둔다. 760px 이하에서는 목록 → 상세(뒤로 버튼)로 나눈다.
- 원칙: 목적이 주인공이다. 숫자는 셀 수 있는 사실(완료 n/m, 미정 n)만 보여 주고 진행률 %·점수를 만들지 않는다. 권한이 없는 동작은 이유를 한 줄로 알린다. 동작 이름은 하나로 쓴다.
- 기본값과 비교해 고친 점: 진행 막대 대신 작업 하나를 점 하나로 그린다(담당자 미정이 프로젝트 안에서 보이도록). 아바타 묶음 대신 이름과 역할을 글로 쓴다. 상단 숫자 칸 줄을 두지 않는다.

## 예시 데이터와 경계

- 이 시안의 가능 여부·불가 사유는 스페이스마다 `exampleActions`로 적어 둔 정적 값이다. 서버 `allowedActions`를 대신해 화면 상태를 보여 줄 뿐이며 역할로부터 권한을 계산하지 않는다. 시안에서 새로 만든 스페이스는 만든 사람을 관리자로 적어 둔다.
- 추가한 예시: "핀잇 개선"에 민지·준호와 프로젝트 "온보딩 안내 정리", 내가 일반 참여자인 "주말 러닝 모임"(관리자 서연), 예시 작업 101–109. 담당자 미정은 `none`으로 기록한다. 이 때문에 오늘에 내 담당 예시 작업 108이 추가로 나온다. 다른 사람이 맡은 작업과 담당자 미정 작업은 오늘에 나오지 않는다.
- 초대 링크는 `/spaces/join/example-link` 예시 문자열이다. 만료·재사용·철회는 서버가 판정한다는 안내만 보여 준다.
- 진행 중(◐) 점은 연결 일정이 진행 중·일시정지일 때만 나온다. 이 상태의 예시는 넣지 않았다.

## 제안 및 미결 사항

- 제안: 사이드바에서 "스페이스" 위치(오늘 바로 다음), 스페이스 표시 색 배정 방식, 점 표시를 막대로 바꾸는 기준(20개), 모바일 진입을 하단 메뉴 대신 스페이스 시트의 "모든 스페이스 보기"로 둔 것.
- 통계 분리 결정에 따른 후속은 0.20.0에서 그렸다(아래 절). BE는 아직 다르게 동작한다: 통계 보고서는 스페이스를 지정하지 않으면 일정의 `ownerId` 기준으로, 지정하면 참여자 전원 기준으로 집계하고, 실행한 사람 기준의 내 통계와 사람별 시간 분해는 없다. 계약 제안은 [요약 API 명세](spaces-summary-api.md)의 "팀 기록과 내 통계" 절에 있다.
- 미결: 요약 API의 구체 계약([제안 명세](spaces-summary-api.md) 작성, 백엔드 리뷰 전), 담당자 필터·배정자 정보 등 그 밖의 BE 계약 확장, 활성 초대 링크를 다시 보는 곳, 프로젝트 스페이스 이동 메뉴. 일정 토글과 통계 범위 표시는 0.19.0에서 그렸다(아래 절).
- 범위 밖: 작업·일정 폼, 오늘, 일정·통계 등 다른 화면의 분석 결과는 이번에 바꾸지 않았다. 작업 카드의 프로젝트 경로와 카테고리 중복 표시도 그대로다.

## 0.19.0 일정·통계의 스페이스 범위

2026-11-09 사용자 확정 결정(팀 스페이스 일정은 내 담당 기본 + 팀 전체 토글, 팀 스페이스 통계는 참여자 전체 합계 + 범위 명시)을 시안에 그렸다.

### 동작

- 일정: 선택한 스페이스(프로젝트를 고른 경우 그 프로젝트)의 일정만 보여 준다. 이전 시안의 일정 화면은 스페이스와 관계없이 모든 일정을 보여 줬다. 브레드크럼은 "핀잇 개선 / 일정"처럼 범위를 보여 준다.
- 팀 스페이스에서는 일정 패널 머리에 "내 일정 | 팀 전체" 전환을 둔다. 기본은 내 일정이고 스페이스를 바꾸면 다시 내 일정으로 돌아간다. 내 일정에서는 그날 숨겨진 팀원 일정 수와 "팀 전체 보기"를 알린다. 팀 전체에서는 일정마다 담당자(나는 파랑, 담당자 미정은 갈색)를 맨 앞에 쓴다.
- 일정의 담당자는 연결된 작업의 담당자를 따른다(확정 정책: 연결 일정은 작업의 소속과 담당을 복사). 작업과 연결되지 않은 일정은 만든 사람(나)으로 본다.
- 개인 스페이스에는 전환이 없다. 오늘의 일정은 스페이스와 관계없이 내 일정만 보여 준다.
- 통계: 선택한 스페이스의 작업·일정으로 다시 계산한다. 위에 "핀잇 개선 참여자 3명 전체의 기록이에요." 또는 "나의 스페이스의 기록이에요."를 쓰고, 부제를 "선택한 스페이스의 기록을 기존 집계 기준으로 돌아보세요."로 바꿨다. 집계 방식(`PinitStats.summarize`)은 바꾸지 않았다.

### 예시 데이터와 구현 경계

- 예시 일정 9101–9104(2026-10-28, 핀잇 개선): 담당자 미정 1개, 준호 1개, 민지 1개, 나 1개.
- 범위 필터는 화면을 그리는 동안에만 전역 일정·작업 배열을 걸러 넣고 곧바로 되돌린다. 그 사이에 저장이 호출돼도 전체 배열을 저장하도록 막았다. 브라우저에서 팀 전체 상태로 일정을 완료한 뒤 저장된 일정이 7개 그대로이고 상태가 반영된 것을 확인했다.
- 권한·담당자 판단 로직은 추가하지 않았다. 예시 데이터의 담당자 값을 읽어 보여 줄 뿐이다.

## 0.20.0 내 통계와 허브의 팀 기록

2026-11-09 사용자 확정 결정(통계 메뉴는 모든 스페이스의 내 기록, 팀 통계는 허브, 시간 지표는 제한 없이 공유, 내 기록은 실제로 실행한 사람 기준)을 시안에 그렸다. 0.19.0의 "통계 화면의 팀 합계" 동작은 대체했다.

### 동작

- 통계 메뉴: 선택한 스페이스와 관계없이 같은 숫자를 보여 준다. 대상은 내가 실행한 일정, 아직 아무도 실행하지 않았다면 내가 맡은 일정, 그리고 내가 맡은 작업이다. 위에 "모든 스페이스에서 내가 실행한 기록이에요. 팀 기록은 스페이스에서 볼 수 있어요."를 쓰고, 브레드크럼은 "모든 스페이스 / 통계"다. 아래에 "스페이스별 내 완료 시간"을 스페이스와 그 안의 프로젝트로 나눠 보여 준다.
- 허브: 참여자가 두 명 이상인 스페이스에 "이번 주 팀 기록"을 담당 영역과 설정 사이에 둔다. 이번 주 완료한 일정 수와 시간, 요일별 막대, 프로젝트별 시간, 실행한 사람별 시간을 보여 준다. 개인 스페이스와 혼자 쓰는 스페이스에는 두지 않는다.
- 시간은 이 시안의 기존 통계와 같이 완료한 일정의 계획 시간이다. BE의 실제 실행 시간(`schedule.getHistory().getElapsedTime()`)으로 바꾸는 것은 구현 단계에서 BE 응답을 따른다. 화면에 "완료한 일정의 계획 시간 기준"을 적었다.
- 막대는 중립 회색이다. 파랑은 실행과 선택에만 쓴다는 원칙을 유지했다.

### 예시 데이터와 구현 경계

- 일정에 실행한 사람 `runner`를 추가했다. 이 시안에서 일정을 시작하거나 완료하면 실행한 사람이 나로 기록되고, 미시작으로 되돌리면 지운다. 이전에 시작·완료된 일정은 담당자를 실행한 사람으로 채운다.
- 예시 완료 일정 9105(민지, 10/27, 60분), 9106(나, 10/27, 30분), 9107(준호, 10/26, 90분, 작업과 연결되지 않은 핀잇 개선 일정)을 추가했다.
- 숫자 계산은 화면 시안의 예시이며, 실제 제품에서는 BE가 집계한다(허브 숫자 출처 결정).
