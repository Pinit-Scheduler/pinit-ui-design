# 팀 스페이스 확정 정책과 UX 명세

2026-11-08 · 명세 전용 · 실제 구현은 백엔드 도메인 담당.

사용자가 추가로 확정한 정책과 UX 상태를 기록한다. 이 문서는 구현 완료 보고가 아니다. 이번 작업의 실시간 동기화·권한·만료·가입 판정용 임시 모의 코드는 철회했다. 기존 승인된 시안의 실행 소스는 커밋 97f5a9d 기준으로 복원하고, 이번 변경은 문서와 저장소 지침으로만 남긴다.

## 사용자 확정 결정

| 항목 | 확정 내용 |
| --- | --- |
| 담당자 미정 | 담당자 없이 등록할 수 있다. 지정된 담당자는 최대 한 명이다. |
| 기본 담당자 | 새 작업은 생성하는 본인에게 기본 배정한다. 필요하면 미정으로 변경할 수 있다. |
| 변경 권한 | 스페이스 참여자 모두 내용과 담당자를 변경할 수 있다. 관리자 역할 지정·위임 권한까지 확대해 해석하지 않는다. |
| 소속 이동 | 언제든 가능하다. 실행 중이라는 이유로 이동을 막지 않는다. 연결 항목의 동반 이동 상세는 별도 결정한다. |
| 삭제·복구 | 해당 스페이스의 관리자만 가능하다. |
| 갱신 | 변경 사항을 실시간으로 갱신한다. |
| 동시 편집 | 낙관적 락으로 충돌 시 저장을 실패시킨다. 갱신·업데이트 주의 문구를 한 번 확인하고 최신 내용으로 갱신한다. |
| 도메인 | 공간 하나당 팀 하나다. 팀 스페이스가 하나의 도메인 개념이며 재사용할 별도 팀 엔티티를 만들지 않는다. |
| 분류 | 카테고리는 프로젝트로 대체한다. |
| 이름 표시 | 회원가입 때 등록한 닉네임을 사용한다. 초대에서 표시 이름을 다시 입력받지 않는다. |
| 초대 | 팀 스페이스 초대 링크를 생성한다. 실제 구현은 Redis에 1시간 만료로 저장한다. |
| 예외 | 중복 참여, 연속 클릭, 만료·취소된 링크, 삭제된 스페이스 등 오류와 재시도를 꼼꼼히 다룬다. |
| 레이어 책임 | 비즈니스 로직은 백엔드 도메인이 소유한다. 애플리케이션부터 UI까지 정책 판단이 누수되지 않게 한다. |
| 이번 작업 범위 | 디자인·UX와 명세만 남긴다. 진짜 구현은 백엔드에서 한다. |

기존 확정 사항인 기본 본인 전용 공간의 초대 금지, 공유 작업 한 건과 공동 상태, 공유 이동 전 과거 기록 공개, 오늘의 모든 공간 내 작업 통합 보기는 유지한다.

## 디자인 기준

기존 핀잇 배경 #F4F6FA, 표면 #FFFFFF, 본문 #202A3C, 보조 #727C8D, 파랑 #345CE5, 선택 #EDF2FF와 Noto Sans KR을 유지한다. 화면의 이름·목적·프로젝트·참여자는 왼쪽 정렬한다. 데스크톱과 모바일에서 같은 동작 이름·순서·권한 설명을 사용한다. 이 문서는 기존 UI에 적용할 화면 명세이며 새 실행 화면이나 독립 프로토타입을 만들지 않는다.

## 화면별 UX 명세

| 화면 | 표시와 입력 | 동작·상태 |
| --- | --- | --- |
| 작업 생성 | 서버가 제공한 기본 담당자의 닉네임. 선택지에 담당자 미정 포함 | 사용자가 미정으로 바꾸지 않으면 생성자 배정. 생략과 명시적 미정은 서버 계약으로 구분 |
| 작업·일정 편집 | 소속 스페이스와 프로젝트, 닉네임 기반 담당자 | 모든 참여자에게 변경 진입 제공. 이동 가능 여부와 결과는 백엔드 응답 사용 |
| 팀 스페이스 관리 | 목적·프로젝트·참여자와 서버가 반환한 내 역할/권한 | 별도 팀 생성 단계를 두지 않음. 본인 전용 기본 공간은 초대 진입을 제공하지 않음 |
| 분류 선택·검색·통계 | 프로젝트 기준 표시 | 기존 카테고리를 별도 분류로 중복 노출하지 않음. 기존 데이터 매핑은 백엔드 이전 정책에 따름 |
| 삭제·복구 | 서버가 반환한 권한과 영향 범위 | 관리자만 실행. 일반 참여자에게 불가 사유 표시. 버튼을 숨기거나 비활성화하는 UX가 서버 권한 검증을 대신하지 않음 |
| 초대 링크 생성 | 링크, 서버 만료 시각, 생성 후 1시간 안내, 복사 | 이메일·임의 표시 이름 입력을 요구하지 않음. 실패하면 사용 가능한 링크가 생긴 것처럼 표시하지 않음 |
| 초대 수락 | 초대한 스페이스, 가입 프로필 닉네임, 공유 기록 안내 | 로그인/회원가입 후 원래 초대 흐름으로 복귀. 닉네임 재입력 없음 |
| 읽는 중 갱신 | 서버의 최신 상태 | 실시간 변경을 반영. 접근 권한 변경·삭제도 서버 결과대로 처리 |
| 편집 중 충돌 | 저장 실패 이유와 갱신 안내 | 한 번 확인한 뒤 최신 내용 표시. 자동 덮어쓰기·무조건 재시도 없음 |

## 초대 상태와 예외 UX

| 서버 처리 결과·상태 | 화면 반응 | 중복·오류 방지 요구 |
| --- | --- | --- |
| 링크 생성 중 | 처리 중 표시, 같은 요청 연속 제출 억제 | UI 중복 클릭 억제와 별개로 서버 생성 결과를 기준으로 함 |
| 생성 성공 | 링크 복사와 1시간 만료 안내 | 서버가 발급한 링크·만료 시각만 사용 |
| 로그인 필요 | 로그인/회원가입 진입 후 초대 흐름 복귀 | 가입한 회원 ID·닉네임으로 수락. 클라이언트가 이름·권한을 만들어 보내지 않음 |
| 참여 처리 중 | 참여 중 표시, 중복 제출 억제 | 서버 저장이 성공하기 전에 참여 성공으로 표시하지 않음 |
| 참여 성공 | 스페이스로 이동 | 회원 ID 기준으로 한 번만 참여 |
| 이미 참여 | 이미 참여 중 안내와 스페이스 이동 | 새 멤버를 만들지 않음. 같은 닉네임 여부로 중복을 판정하지 않음 |
| 연속 클릭·동시 요청·재시도 | 동일한 참여 결과로 수렴 | 스페이스 ID+회원 ID 중복 방지를 서버가 원자적으로 보장 |
| 만료·취소·잘못된 링크 | 참여 불가와 새 링크 요청 안내 | 서버의 검증 결과 사용. Redis 키가 없어 이유를 구분할 수 없으면 유효하지 않거나 만료된 링크로 안내 |
| 삭제된 스페이스 | 더 이상 참여할 수 없음 안내 | 삭제·수락 경쟁 상황도 백엔드에서 검증 |
| Redis·저장소·네트워크 실패 | 처리 실패, 재시도 진입 | 실패를 참여 성공으로 처리하지 않음. 재시도에도 중복 멤버가 생기지 않아야 함 |
| 수락 직전 만료·권한 변경 | 최신 서버 결과에 따른 실패/이동 | 화면을 열었을 때의 클라이언트 상태로 수락을 승인하지 않음 |

복원된 스페이스에서 과거 링크를 다시 쓸지, 링크를 여러 사람이 재사용할지, 링크 생성·철회 권한을 누구에게 줄지는 아직 결정하지 않았다. 삭제 시 기존 링크를 철회하고 복원 후 새로 발급하는 방식을 검토안으로 권장하며 확정 요구와 구분한다.

저장되지 않은 입력을 별도로 펼쳐 확인하거나 복사할 수 있게 하는 것은 UX 제안이다. 서버의 충돌 결과를 받은 뒤 한 번 안내하며, UI가 버전을 비교해 저장 가능 여부를 독자 승인하지 않는다.

## 아직 남은 세부 결정

- 일정의 소유자·공용 실행 상태·작업당 연결 일정 수.
- 연결 항목의 동반 이동, 프로젝트 통째 이동과 선후 관계·실행 기록 처리.
- 추가 공간의 목적 생략·프로젝트 없는 기록 허용과 기존 분류의 구체적 이전 방식.
- 최초 관리자 지정·위임·마지막 관리자 탈퇴, 참여자 제외 권한, 초대 링크 생성/철회 권한.
- 링크의 다회 사용·사용 횟수, 스페이스 복원 후 과거 링크 처리.
- 삭제 보관 기간·복원 충돌, 기록 종류별 공개 범위·개인 공간으로 되돌린 후 접근.
- 자동 완료·목적 달성·프로젝트 보관, 반복·계획·통계의 공유 범위, 담당자 미정 작업의 오늘 집계 상세.
- 실제 구현 우선순위·사용성 평가 기준.

## 구현 인계와 검증 범위

[백엔드 도메인 책임과 계약](backend-domain-boundary.md)에 책임 경계와 백엔드 수용 조건을 기록한다. AGENTS.md에도 명세 전용 범위와 비즈니스 로직의 백엔드 도메인 소유 원칙을 남긴다.

이번 완료 기준은 확정/미결 구분, UX 상태·문구, 백엔드 계약의 일관성과 문서만 변경되었는지 확인하는 것이다. 실제 Redis·DB·인증·실시간 통신·낙관적 락 구현과 검증은 수행하지 않는다. 철회한 임시 모의 구현이나 그 실행 결과를 제품 구현 증적으로 사용하지 않는다.
