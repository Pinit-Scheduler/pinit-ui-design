# 스페이스 요약 API 명세 (제안)

2026-11-09 · 명세 전용 · 실제 구현은 백엔드 도메인 담당.

## 상태

- **사용자 확정**: 스페이스 허브의 숫자는 백엔드가 요약으로 내려 준다. 미완료·진행 중 같은 정의는 백엔드 도메인이 소유하고, FE는 작업 목록을 받아 직접 세지 않는다.
- **이 문서의 경로·필드·정의**: 리뷰용 제안이다. 백엔드 리뷰에서 확정하기 전까지 구현 계약이 아니다.
- 이 저장소에는 요약을 계산하는 실행 코드를 추가하지 않는다. 시안의 숫자는 예시 데이터로 그린 것이다.

## 근거로 확인한 현재 백엔드 (pinit-monolith `a806512d`)

| 대상 | 확인한 내용 |
| --- | --- |
| Task | `spaceId`, `projectId`, `assigneeId`(null = 담당자 미정), `completed`, `deletedAt`(휴지통), 마감일과 마감 시간대(`temporalConstraint`) |
| Schedule | `taskId`, `assigneeId`, `state`(`NOT_STARTED`·`IN_PROGRESS`·`SUSPENDED`·`COMPLETED`), `deletedAt`. 계약상 작업 하나에 살아 있는 일정은 최대 하나 |
| 스페이스 조회 | `GET /v2/spaces` → `SpaceList(defaultSpaceId, currentMember, spaces)`, `GET /v2/spaces/{id}/snapshot` → `SpaceSnapshot(space, projects, members)`. 숫자 요약은 없다 |
| 실시간 | `GET /v2/workspace/events`의 `changed` = `{spaceId, resourceType, resourceId, version, action}`. 이벤트마다 멤버십을 다시 확인한다 |
| 통계 | 스페이스를 지정하면 접근 가능한 참여자 전원의 항목을 집계한다(`findAllVisible`) |

## 화면이 필요로 하는 숫자

| 위치 | 숫자 |
| --- | --- |
| 스페이스 목록(모든 스페이스) | 참여자 수, 미완료 작업 수 |
| 프로젝트 행 | 전체 작업 수, 상태별 수(완료·진행 중·담당자 미정·그 밖의 미완료), 가장 가까운 마감일 |
| 프로젝트 없이 기록한 작업 | 위와 같은 구성 |
| 참여자 행 | 그 사람이 맡은 미완료 작업 수, 가장 가까운 마감일 |
| 담당자 미정 | 미완료 작업 수, 가장 가까운 마감일 |

점 표시는 상태별 수만 있으면 그릴 수 있다. 작업 목록이나 개별 상태는 내려 주지 않아도 된다.

## 제안 경로

기존 `SpaceList`·`SpaceSnapshot` 응답은 MCP 등 다른 소비자가 있으므로 바꾸지 않고, 읽기 전용 경로 두 개를 추가한다.

### 1. `GET /v2/spaces/summaries`

호출자가 현재 참여 중인 활성 스페이스마다 한 줄씩 돌려준다.

```json
{
  "asOf": "2026-11-09T05:30:00Z",
  "spaces": [
    { "spaceId": -12, "memberCount": 1, "openTaskCount": 4, "unassignedOpenCount": 0 },
    { "spaceId": 31, "memberCount": 3, "openTaskCount": 7, "unassignedOpenCount": 2 }
  ]
}
```

### 2. `GET /v2/spaces/{id}/summary`

```json
{
  "spaceId": 31,
  "asOf": "2026-11-09T05:30:00Z",
  "projects": [
    { "projectId": 88, "counts": { "total": 4, "completed": 1, "running": 0, "unassigned": 1, "open": 2 }, "nearestDueDate": "2026-10-29" }
  ],
  "withoutProject": { "counts": { "total": 0, "completed": 0, "running": 0, "unassigned": 0, "open": 0 }, "nearestDueDate": null },
  "members": [
    { "memberId": 7, "openAssignedCount": 1, "nearestDueDate": "2026-10-29" }
  ],
  "unassigned": { "openCount": 2, "nearestDueDate": "2026-10-31" }
}
```

- 프로젝트 이름·성과·완료 여부와 참여자 닉네임·역할은 기존 `snapshot`이 이미 준다. 요약은 ID와 숫자만 담고, FE는 둘을 ID로 합친다.
- `counts`의 네 상태는 서로 겹치지 않으며 합이 `total`이다.
- 삭제되지 않은 프로젝트는 완료 여부와 관계없이 모두 포함한다. 완료한 프로젝트를 접어 보이는 건 화면이 `ProjectView.completed`로 판단한다.

## 정의 (제안 — 백엔드 도메인이 확정)

| 이름 | 제안 정의 |
| --- | --- |
| 대상 작업 | `spaceId`가 해당 스페이스이고 `deletedAt`이 없는 작업. 휴지통 항목은 세지 않는다 |
| 완료 `completed` | `Task.completed = true` |
| 진행 중 `running` | 완료가 아니고, 연결된 살아 있는 일정의 상태가 `IN_PROGRESS` 또는 `SUSPENDED` |
| 담당자 미정 `unassigned` | 완료·진행 중이 아니고 `assigneeId`가 null |
| 그 밖의 미완료 `open` | 위 셋에 해당하지 않는 작업 |
| 미완료 작업 수 | `completed`가 아닌 대상 작업 수(진행 중·담당자 미정 포함) |
| 맡은 미완료 | `completed`가 아니고 `assigneeId`가 그 참여자인 작업 수 |
| 가장 가까운 마감일 | 해당 묶음의 미완료 작업 중 가장 이른 마감일. 각 작업의 마감 시간대 기준 날짜(`yyyy-MM-dd`). 이미 지난 날짜도 포함 |

상태의 우선순위는 완료 → 진행 중 → 담당자 미정 → 그 밖의 미완료 순이다. 담당자가 없는데 일정이 진행 중인 작업은 진행 중으로 센다.

## 권한과 범위

- 호출자가 그 스페이스의 현재 참여자일 때만 응답한다. 참여자가 아니거나 삭제된 스페이스는 기존 스페이스 조회와 같은 오류 규칙을 따른다.
- 팀 스페이스에서는 호출자 본인 것만이 아니라 참여자 전원의 작업을 센다. 허브가 팀 현황을 보여 주는 화면이기 때문이다(사용자 확정: 팀 통계도 참여자 전체 기준).
- 개인 스페이스도 같은 형식으로 응답한다. 참여자는 본인 한 명이다.
- 기존 MCP 연결의 범위는 넓히지 않는다. 이 요약을 MCP 도구로 노출할지는 별도로 정한다.

## 갱신과 실시간

- 요청 시점에 계산하는 읽기 전용 응답으로 제안한다. 별도 저장 테이블이나 새 쓰기 경로를 만들지 않는다. `asOf`는 계산 시각이다.
- 새 실시간 이벤트 종류는 필요하지 않다. FE는 그 스페이스의 `changed`(작업·일정·프로젝트·멤버십 변경)를 받으면 요약을 다시 조회하고, 재연결 때도 다시 조회한다. 여러 이벤트가 몰리면 묶어서 한 번만 조회한다.
- 요약은 편집 대상이 아니므로 버전이나 낙관적 락이 필요 없다.

## 백엔드 수용 조건 (제안)

1. 두 경로 모두 현재 멤버십을 검사하고, 참여하지 않은 스페이스의 숫자를 노출하지 않는다.
2. 상태별 수의 합이 `total`과 같고, 정의 표의 우선순위를 따른다.
3. 휴지통 작업, 삭제된 프로젝트, 다른 스페이스로 이동한 작업은 이동 후 스페이스에서만 센다.
4. 참여자가 나가거나 제외되면 그 사람은 `members`에서 빠지고, 남은 작업의 집계는 도메인의 담당자 처리 결과를 그대로 따른다.
5. 같은 데이터에 대해 요약의 숫자와 작업 목록 API(`spaceId`, `projectId`, `mine` 필터)의 결과가 어긋나지 않는다.
6. 스페이스·프로젝트 수가 늘어도 요청 하나당 쿼리 수가 작업 수에 비례하지 않는다(묶음 집계).

## 이번 범위가 아닌 것

- 팀 스페이스 일정의 "내 담당 / 팀 전체" 전환은 기존 일정 조회의 `mine` 파라미터로 처리할 수 있어 이 API가 필요 없다.
- 통계 화면의 범위 표시는 기존 통계 응답을 그대로 쓰고 화면 문구만 바꾼다. 프로젝트별·담당자별 통계 분해는 다음 단계다.
- 담당자별 작업 목록 필터, 배정한 사람·시각 정보는 별도 계약 확장으로 검토한다.

## 백엔드 리뷰에서 정할 질문

1. 미래에 생성된 반복 회차를 미완료 수에 넣을지, 일정 기간 안의 회차만 셀지. 반복이 많으면 숫자가 커진다.
2. 놓친 반복 회차(`isMissed`)를 미완료로 셀지, 따로 셀지.
3. 진행 중의 기준에 `SUSPENDED`(일시정지)를 넣는 것이 맞는지.
4. 나간 참여자가 맡았던 작업이 도메인에서 어떻게 처리되는지(담당자 미정으로 바뀌는지), 그 결과를 요약이 그대로 따르면 되는지.
5. 스페이스 목록 요약을 별도 경로로 둘지, `GET /v2/spaces` 응답에 선택적으로 붙일지.
