# 모션 레이어와 깜빡임 없는 다시 그리기

2026-11-10 · 디자인 시안 0.22.0 · `origin/main`(`f932f66`)에서 `claude/motion-no-flicker`로 분기.

FE가 따를 모션 명세다. 시안의 소스는 `motion.css`와 `motion.js`이며 빌드 순서의 맨 마지막에 붙는다. 기능, 데이터, 문구, 정렬은 바꾸지 않는다. 다른 모듈이 정의한 전역 함수(`navigate`, `toggleTask`, `changeStateV2`)를 마지막에 한 번 감싸고, 목록·대화상자·토스트·플레이어는 DOM에서 관찰한다.

## 출발점

- 사용자 보고(2026-11-10): 운영 FE에서 화면을 바꿀 때와 작업을 만들거나 완료한 뒤 화면이 깜빡인다. 사용성을 해치지 않는 선에서 모든 곳에 넉넉한 모션을 원하고, 특히 완료 순간을 원한다.
- 이 시안의 현재 동작(관찰): 목록은 `innerHTML`로 통째로 다시 그린다. 모든 행이 새 DOM이 되어 CSS 전환이 작동하지 않고, 진입 애니메이션을 행 선택자에 걸면 다시 그릴 때마다 모든 행이 다시 재생된다. 이것이 "깜빡임"과 같은 종류의 문제다. 기존 애니메이션은 스페이스 시트 진입(`.14s`/`.18s ease-out`)과 진행 막대 `width .3s` 정도였다.
- 운영 FE 코드(`pinit-fe`)는 이 작업에서 읽거나 바꾸지 않았다. FE의 깜빡임 원인(리마운트, 로딩 상태 교체, 쿼리 무효화 등)은 확인하지 않았고, 아래 FE 적용 지침은 같은 토큰을 쓰는 병렬 FE 작업을 위한 제안이다.

## 토큰 (확정 값)

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--motion-ease` | `cubic-bezier(0.2,0,0,1)` | 진입·이동·색 변화. 빨리 시작해 부드럽게 멈춘다. |
| `--motion-ease-exit` | `cubic-bezier(0.4,0,1,1)` | 퇴장. 천천히 시작해 빨리 사라진다. |
| `--motion-fast` | `120ms` | 눌림 반응, 교체, 다시 열기, 줄인 모션의 페이드 |
| `--motion-base` | `180ms` | 행 이동(FLIP), 색 변화, 숫자 변화, 체크 획 |
| `--motion-enter` | `240ms` | 화면·행·대화상자·시트 진입, 완료 취소선 |
| `--motion-exit` | `160ms` | 행·대화상자·토스트·플레이어 퇴장 |
| `--motion-distance` | `8px` | 진입 상승 거리. 퇴장은 절반(4px), 플레이어는 두 배(16px) |

## 원칙

1. 차분하고 정확하게, 조용히 만족스럽게. 짧게 감속하는 움직임만 쓴다. 튕김, 반복, 맥박, 시차 없음.
2. `transform`(개별 `translate`·`scale` 속성), `opacity`, 색(`color`·`background-color`·`border-color`·`text-decoration-color`), `stroke-dashoffset`만 움직인다. 너비·높이·위치·여백·흐림은 움직이지 않는다. 토스트와 플레이어는 이미 `transform: translateX(-50%)`로 가운데 정렬하므로 `translate` 속성으로 겹쳐 쓴다.
3. 진입 애니메이션은 기본 선택자에 걸지 않는다. "새로 생긴 것"에만 클래스로 건다. 다시 그려도 그대로인 것은 움직이지 않는다.
4. 사라지는 것은 데이터에서 이미 빠졌어도 퇴장 한 번만큼 화면에 남는다. 남은 것은 `aria-hidden`과 `inert`로 읽히지도 눌리지도 않고, `id`를 지워 `getElementById`와 겹치지 않는다.
5. 줄인 모션(`prefers-reduced-motion: reduce`)에서는 불투명도만 `--motion-fast`로 바뀐다. 이동, 획 그리기, 취소선 그리기, 숫자 세기, FLIP은 하지 않는다. 색 변화는 움직임이 아니므로 남긴다.
6. 모션 때문에 기다리게 하지 않는다. 데이터 변경, 저장, 토스트, 초점 복귀는 지금과 같은 시점에 일어난다. 애니메이션 도중에도 새 입력을 받는다.

## 동작

### 1. 화면 전환

- 사이드바·하단 메뉴의 `[data-nav]` 클릭은 View Transitions로 감싼다. 본문(`.content`, `view-transition-name: m-content`)만 이전 화면이 `--motion-exit`로 사라지고 새 화면이 `--motion-enter` 동안 8px 올라오며 나타난다. 루트(사이드바, 상단 바, 메뉴)는 애니메이션 없이 그대로 바뀐다. 본문 크기 변화는 애니메이션하지 않는다(`view-transition-group` 0s).
- 원래 클릭 처리기는 그대로 실행된다. 캡처 단계에서 클릭을 잠시 멈추고, 전환의 업데이트 콜백 안에서 같은 버튼을 다시 클릭한다. 프레임이 오지 않는 환경(백그라운드 탭 등)에서는 150ms 뒤 바로 이동하고 전환을 건너뛴다.
- 코드에서 `navigate()`를 직접 부르는 경우(허브의 프로젝트 이동, 데모 초기화 등)는 동기 호출을 기대하는 코드가 있어(`navigate('tasks'); refreshPurposeCrudV17(...)`) 미루지 않는다. 대신 바뀐 본문이 `.m-screen-in`으로 올라온다.
- 화면이 실제로 바뀌면 맨 위로 스크롤한다. 같은 화면을 다시 부르면 스크롤도 모션도 없다.
- 화면 전환이 그린 프레임 동안은 목록 단위 모션을 멈춘다. 새 화면의 행이 하나씩 날아들지 않는다.

### 2. 깜빡임 없는 다시 그리기 (키 기반 존재 관리)

- `Element.prototype.innerHTML` 설정을 감싸, 행(`.task`, `.schedule-row`, 허브 행 등)을 담은 요소가 다시 그려질 때 직전 상태를 기록하고, 같은 작업이 끝난 뒤(마이크로태스크, 첫 페인트 전) 비교한다. 한 번의 처리에서 같은 목록을 여러 번 그려도 처음 상태와 마지막 상태만 비교한다.
- 키: `data-task-id`, `data-schedule-id` 등 데이터 속성 → 없으면 첫 클래스와 `onclick` 동작 → 없으면 제목 텍스트. 같은 키가 여러 번 나오면 순번을 붙인다(오늘 화면에서 한 작업이 "오늘 마감"과 "바로 시작" 두 곳에 나오는 경우).
- 남은 키: 진입 없이 제자리. 위치가 바뀌었으면 FLIP으로 `--motion-base` 동안 옮긴다. 상태 색이 바뀌었으면 이전 계산 색에서 새 색으로 `--motion-base` 동안 바뀐다(Web Animations). 새 DOM이어도 색 전환이 이어진다.
- 새 키: 30ms 간격(최대 120ms 지연)으로 8px 올라오며 나타난다.
- 빠진 키: 이전 노드를 이전 자리에 절대 위치로 다시 놓고 `--motion-exit` 동안 4px 올라가며 사라진 뒤 지운다. 남은 행은 FLIP으로 빈자리를 메운다.
- 목록 전체가 바뀌면(겹치는 키 없음, 4개 이상) 행마다 움직이지 않고 목록이 `--motion-fast` 동안 60%에서 100%로 짙어진다. 처음 채워지는 목록(이전에 행이 없고 4개 이상), 화면에 보이지 않는 목록, 120개를 넘는 목록은 움직이지 않는다. 빠지는 행이 8개를 넘으면 퇴장 잔상을 만들지 않는다.

### 3. 완료 서명 동작

작업 체크(`toggleTask`)를 감싸 완료 여부가 실제로 바뀐 행에만 건다. 총 약 480ms, 진행 중에도 다른 입력을 받는다.

| 시간 | 완료 | 다시 열기 |
| --- | --- | --- |
| 0ms | 상자가 강조색(`--blue`)으로 찬다 | 상자가 비워진다(`--motion-fast`) |
| 60–240ms | 체크가 펜 획처럼 그려진다(`stroke-dashoffset` 1→0, `pathLength=1`) | — |
| 120–360ms | 제목 취소선이 왼쪽에서 오른쪽으로 그려진다(`::after`의 `scale` X 0→1) | 취소선이 오른쪽으로 거둬진다(`--motion-fast`) |
| 220–460ms | 제목이 기본 글자색에서 완료 회색(`#9aa4b3`)으로, 상자가 강조색에서 완료 회색(`#8c9bb5`)으로 가라앉는다 | 제목이 회색에서 기본색으로 |

- 한 줄 제목은 정적인 완료 상태에서도 같은 `::after` 선을 쓴다(`.m-strike`, 애니메이션 끝과 정지 상태의 선 위치가 같다). 두 줄 이상으로 감기는 제목(모바일에서 흔함)은 기존 `line-through`를 유지하고, 완료할 때 취소선 색이 투명에서 나타난다. 줄 수는 렌더와 창 크기 변경 때 다시 잰다.
- 오늘 화면에서 완료한 작업이 "바로 시작할 수 있는 작업"에서 빠지면 그 행은 퇴장하고, 새로 시작 가능해진 다음 작업은 진입한다. 숫자는 아래 5번처럼 바뀐다.
- 일정도 같은 계열이다(`changeStateV2` 감쌈). 상태 아이콘과 일정 본문의 배경·테두리·글자색이 이전 색에서 새 색으로 바뀌고 본문이 60%에서 짙어진다. 완료는 상태 아이콘이 위에서 내려앉는다. 하단 플레이어는 시작하면 16px 아래에서 올라오며 나타나고, 일시정지·재개하면 상태 글자만 바뀌며, 완료·취소하면 아래로 내려가며 사라진다.

### 4. 대화상자, 시트, 토스트

- `#modalRoot`, `#toastRoot`, `#playerV2`의 자식 추가·삭제를 관찰한다. 어떤 코드 경로로 열고 닫아도 같은 모션이 적용된다.
- 대화상자: 배경이 `--motion-base` 동안 나타나고 패널이 8px 올라온다. 닫으면 배경이 `--motion-exit` 동안 사라지고 패널이 8px 내려간다. 열린 대화상자를 다른 대화상자로 바꾸거나(검색 → 상세) 닫자마자 다른 대화상자를 열면 배경을 다시 깜빡이지 않는다(교체로 보고 모션 없음). 이 시안의 일반 대화상자는 모바일에서도 가운데에 뜨므로 같은 상승을 쓴다.
- 시트(스페이스 전환 `<dialog>`): 760px 이하에서는 화면 아래에서 끝까지 미끄러져 올라오고(`--motion-enter`) 닫으면 내려간다(`--motion-exit`). 넓은 화면의 패널은 4px 위에서 내려앉는다. 기존 `.14s/.18s ease-out` 애니메이션을 토큰으로 바꿨다. Esc(`cancel`)도 퇴장을 거친다. 퇴장 중에 다시 열면 즉시 닫고 다시 연다.
- 토스트: 4px 위에서 내려앉으며 나타나고 사라질 때 올라가며 흐려진다. 토스트가 다른 토스트로 바뀌면 이동 없이 60%에서 짙어진다.

### 5. 숫자

- `#taskCount`, `#sideCount`, 오늘 구역 제목의 숫자, `#progressPercent`, 허브 숫자 등은 값이 바뀌면 3px 위에서 내려앉고, 2 이상 차이 나면 `--motion-base` 동안 이전 값에서 새 값까지 센다. 마지막 글자는 항상 원래 코드가 쓴 값과 같다. 고정폭 숫자(`tabular-nums`)로 자릿수 흔들림을 막는다.
- 진행 막대는 기존 `width .3s` 전환을 그대로 둔다(아래 미결 사항).

## FE 적용 지침 (제안)

이 시안은 문자열 렌더링 위에 덧댄 방식이다. React FE에서는 같은 결과를 더 간단히 얻는다.

1. 목록 행은 서버 id를 `key`로 쓰고, 다시 불러오는 동안 목록을 스켈레톤·빈 상태로 바꾸지 않는다(이전 데이터 유지). 이것만으로 대부분의 깜빡임이 사라진다. 진입 애니메이션은 마운트 시점이 아니라 "이번에 새로 생긴 id"에만 건다.
2. 완료는 낙관적 업데이트 직후 해당 행에 완료 클래스를 붙여 위 시간표대로 재생한다. 서버 응답으로 다시 그려도 같은 `key`이면 재생되지 않는다. 실패하면 다시 열기 모션으로 되돌린다.
3. 화면 전환은 라우터 전환을 `document.startViewTransition`으로 감싸고, 앱 셸 밖의 본문에만 `view-transition-name`을 준다. 지원하지 않는 브라우저는 본문 진입(`m-rise`)만 쓴다.
4. 대화상자·시트·토스트는 닫힘 상태에서 퇴장 애니메이션이 끝난 뒤 언마운트한다(`onAnimationEnd` 또는 `--motion-exit` 타이머). 교체일 때는 배경을 다시 재생하지 않는다.
5. 토큰 이름과 값은 위 표를 그대로 쓴다.

실행한 것:

- `npm run check`(모든 구문 검사와 `task-map`·`task-matrix`·`stats`·`map-overview` 테스트) 통과, `npm run build` 통과.

  - 줄인 모션 그대로, 새 탭에서: 1365×900은 사이드바 클릭으로 작업·일정·스페이스·통계·작업 맵·매트릭스·오늘 전환, 작업 완료와 다시 열기, 상세 대화상자 열고 닫기, 검색 → 상세 교체 후 닫기, 일정 시작·일시정지·취소, 스페이스 패널 열고 닫기. 390×844는 하단 메뉴로 작업·일정·통계·작업 맵·오늘 전환과 나머지 같은 흐름, 스페이스 시트 열고 닫기. 두 폭 모두 콘솔 오류 0건, 가로 스크롤 없음, 끝난 뒤 남은 잔상 0개. 390×844에서는 모든 화면(오늘, 스페이스, 일정, 작업, 통계, 작업 맵, 매트릭스, 생활 시간, 반복 관리, 휴지통, 설정)을 `navigate()`로 열어 가로 스크롤이 없음을 확인했다.
  - 전체 모션: 같은 페이지의 미디어 쿼리 문자열만 바꾼 사본을 iframe(srcdoc)으로 열어 `document.getAnimations()`로 확인했다. 완료 시 `m-check-fill`, `m-draw`, `m-strike-draw`(`::after`), `m-settle`, 빠진 행의 `m-leave` 잔상, 남은 행의 FLIP `translate` 전환, 새로 시작 가능한 행의 `m-rise`, 숫자 `m-tick`, 다시 열기의 `m-check-empty`·`m-strike-undraw`·`m-unsettle`, 일정 상태의 색 전환(Web Animations)과 `m-tick`, 플레이어 `m-player-in`/`m-player-out`, 대화상자 `m-open`·잔상, 모바일 시트 `m-sheet-in`/`m-sheet-out`과 배경, 메뉴 클릭의 화면 전환과 맨 위 스크롤을 확인했다. 오류 0건.
- 모든 화면에서 `#content` 안에 `position: fixed` 요소가 없음을 확인했다(본문 `translate`가 고정 요소를 밀지 않음).

확인하지 못한 것:

- 내장 브라우저 창이 숨겨진 상태라 애니메이션 프레임이 진행되지 않았다. 각 애니메이션이 올바른 요소에 걸리고 끝난 뒤 클래스와 잔상이 정리되는 것은 확인했지만, 프레임 단위의 실제 모양(속도감, 겹침, 취소선 위치의 1px 차이 등)은 눈으로 보지 못했다. View Transitions도 이 환경에서는 프레임이 오지 않아 150ms 대체 경로로 이동했다. 실제 크로스페이드는 보이는 브라우저에서 다시 확인해야 한다.
- 실제 터치 기기, Safari, Firefox(View Transitions 미지원 시 대체 경로)는 확인하지 않았다.
- 작업 추가 폼은 이 시안의 기존 검증(설명 필드)에 막혀 끝까지 저장하지 못했다. 새 행 진입은 같은 렌더 경로에 예시 작업을 넣어 확인했다. 폼 동작은 바꾸지 않았다.
- 화면 캡처는 남기지 않았다.

## 제안 및 미결 사항

- 진행 막대(`#progressBar`)는 기존 코드가 `style.width`를 직접 바꾸고 `width .3s`로 전환한다. 원칙 2에 맞추려면 FE에서는 `scaleX`로 그리기를 제안한다. 시안은 기존 동작을 유지했다.
- 완료 직후 행이 다른 위치로 정렬되는 목록(FE의 완료 아래로 보내기 등)에서는 서명 동작이 제자리에서 끝난 뒤(약 300ms) 이동하도록 정렬을 늦출지 결정이 필요하다. 이 시안의 목록은 완료로 순서가 바뀌지 않아 그리지 않았다.
- 체크 버튼을 누르면 행이 새 DOM이 되어 초점이 사라진다(기존 동작). FE에서는 같은 `key`로 초점이 유지되는지 확인이 필요하다.
