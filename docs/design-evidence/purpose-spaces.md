# 핀잇: 기존 UI의 목적 공간 탐색

상태: 기존 시안 소스 수정 및 아래 범위의 로컬 검증 완료. 예시 데이터만 사용하며 제품 API에 연결하지 않는다.

## 사용자에게 확인한 방향

- 제품명은 핀잇(Pinit)이다.
- 개인 작업이 우선이다. 오늘에서는 여러 공간의 내 할 일을 모아 본다.
- 기존 pinit-ui-design 화면을 직접 수정한다. 별도 화면을 새로 만들어 기존 UI 수정처럼 제시하지 않는다.
- 화면은 반응형이며, 향후 앱으로 이어 쓸 수 있는 디자인 완성도와 터치 사용성을 고려한다.
- 디자인 변경은 저장소 소스, 검증 증적과 커밋으로 남긴다.
- 사용자가 frontend-design 스킬의 설치와 사용을 요청하여 Anthropic 공식 배포본을 설치하고 전체 지침을 읽었다.

## 디자인 계획과 자체 검토

기존 화면의 작업 카드, 시간표, 카테고리, 중요도·난이도 표현을 유지한다. 공간 탐색을 같은 앱 안의 맥락 이동으로 표현한다.

- 색: 기존 기본 배경 #F4F6FA, 표면 #FFFFFF, 본문 #202A3C, 보조 글자 #727C8D, 실행·선택 #345CE5, 선택 배경 #EDF2FF를 유지한다. 구현은 기존 테마 변수로 연결한다.
- 글자: 기존 Noto Sans KR을 유지한다. 페이지 제목이 가장 강하고, 공간 이름·선택 항목·보조 설명의 순서로 위계를 둔다. 메뉴 본문은 왼쪽 정렬한다.
- 배치: 데스크톱에서는 왼쪽 위 공간 버튼 아래에 선택 패널을 붙인다. 모바일에서는 같은 내용을 하단 시트로 열어 손가락 접근과 안전 영역을 확보한다.
- 원칙: 현재 선택, 기본 개인 공간의 본인 전용 여부, 목적 공간의 이름을 선택 전에 읽을 수 있게 한다. 오늘의 전체 공간 범위는 선택 패널 안에서도 알려 준다.

```text
데스크톱                         모바일
[공간 버튼]                     [공간 버튼] [현재 화면]
  └ 공간 선택 패널              [기존 작업 목록]
[기존 메뉴 / 프로젝트]          [하단 메뉴]
[기존 작업 목록 / 시간표]       └ 화면 아래에서 공간 선택 시트
```

자체 검토: 브라우저 기본 select는 기존 앱의 표면·글자·간격을 제어하기 어렵고 모바일 앱의 선택 경험과도 연결되지 않았다. 이를 단순히 장식한 목록으로 바꾸기보다, 두 화면 크기에서 위치와 상호작용이 맞는 하나의 공간 전환 컴포넌트로 수정했다. 기존 앱을 새로운 스타일로 덮어씌우지 않고 공간 선택에만 강조를 집중한다.

## 이 시안의 동작

- 오늘: 기존 오늘 마감·바로 시작할 수 있는 작업의 조건과 구역을 그대로 유지한다. 공간 선택으로 이 화면의 조회 범위를 좁히지 않는다. 두 조건에 모두 해당하는 작업은 기존처럼 양쪽에 표시된다.
- 공간 선택: 오늘의 전체 목록을 유지하면서 탐색할 공간을 바꾼다. 프로젝트를 선택하면 기존 작업 목록이 그 프로젝트로 좁혀진다.
- 프로젝트: 목적과 기여할 성과를 펼쳐 보고 프로젝트 자체의 완료·재개를 표시한다. 하위 작업의 상태를 자동으로 바꾸지 않는다.
- 작업 카드와 상세: 공간·프로젝트 소속을 표시하고 기존 상세, 수정, 완료 및 일정 배정 동작을 이어 쓴다.
- 새 작업: 프로젝트 안에서 추가하면 그 프로젝트에, 그 밖에는 기본 개인 공간에 담는 탐색 시안이다. 기존 항목의 임의 재분류나 실제 계정 데이터 변경은 없다.
- 기본 개인 공간에는 초대 동작을 제공하지 않는다.

## 제안 및 미결 사항

예시 공간·목적·프로젝트 이름과 기존 예시 작업의 소속은 화면 검토용 제안이다. 실제 사용자 데이터의 이동 결과가 아니다. 공간 생성·초대, 공유 일정의 소유와 공개 범위, 담당자 미정, 이동·삭제·복구, 동시 수정 및 공간별 통계 정책은 이 시안으로 확정하지 않는다. 일정·작업 맵·통계의 기존 예시 동작은 유지한다.

## 검증 기록

검사와 화면 확인 결과는 아래에 최종 결과를 기록한다. 실행하지 않은 항목을 통과로 표시하지 않는다.

- `npm run check` 통과: 기존 그래프·매트릭스·통계·축약 배치 검사 및 신규 화면 스크립트 구문 검사.
- `npm run build` 통과: 기존 소스에 새 CSS/JS를 묶고 생성된 인라인 스크립트 구문 확인.
- 오늘의 기존 구역 복원 확인: 오늘 마감 3건, 시작 가능 3건이며 예시 작업 ID 1은 두 구역에 모두 표시된다. 공간을 바꿔도 이 구역과 항목 배열이 유지됐다.
- 데스크톱: 버튼 아래 공간 선택 패널, 선택 상태, 선택 후 닫기와 포커스 복귀, 카드 소속을 통한 프로젝트 이동 확인.
- 프로젝트: 선택한 작업 카드 개선 프로젝트에는 예시 작업 2만 표시됐다. 프로젝트 완료 표시가 작업 완료를 바꾸지 않았고 재개 후 원상태로 돌렸다. 기존 작업 추가 폼의 필드와 해당 프로젝트 소속 안내도 확인했다.
- 모바일: 실제 DOM 너비 320px·높이 740px에서 시트 좌우 경계가 0..320px, 하단이 740px였다. 선택 항목 높이는 각 72px, 프로젝트 선택 버튼은 44px였다. 가로 넘침이 없고 시트를 열면 배경 스크롤이 잠기며 Escape 후 닫힘·포커스 복귀·스크롤 복원이 확인됐다.
- 기존 작업 맵에서 전체 예시 작업 5건과 연결 상태를 확인했다. 통계 화면 진입과 일정 화면의 3건 표시를 확인했다. 이 확인은 실제 서비스 API·통계·상태 전이의 재검증을 뜻하지 않는다.
- 최종 브라우저 오류 로그는 비어 있었다. 임시 화면 크기 설정은 원래대로 돌렸다.

화면 증적: [데스크톱 오늘](purpose-spaces/desktop-today.png), [데스크톱 공간 선택](purpose-spaces/desktop-picker.png), [프로젝트](purpose-spaces/desktop-project.png), [모바일 공간 선택](purpose-spaces/mobile-picker.png). 철회한 작업 재분류 화면은 이 증적에 포함하지 않는다.

## 지식베이스 및 업무 기준 확인

최초 검토에서 두 구역에 같은 작업이 표시되는 것을 오류로 잘못 단정했다. 사용자의 지적 후 [지식베이스의 FE 흐름](https://github.com/Pinit-Scheduler/pinit-docs/blob/main/docs/design/frontend.md)과 [실제 TodayPage](https://github.com/Pinit-Scheduler/pinit-fe/blob/58e4c5816d3c3b80aaa383ae3ef91bf357eb33c5/src/features/today/pages/TodayPage.tsx)를 읽었다.

TodayPage는 시작 가능 작업 미리보기와 해당 날짜 마감 작업을 별도 요청하고 각각 렌더링한다. 두 목록에서 한 번만 보이게 할 필터는 없다. 따라서 조건의 교집합에 있는 작업이 양쪽에 표시되는 사실만으로 결함이라고 판단할 근거가 없다. FE 문서의 고정 코드와 대조한 현재 기본 브랜치에서 TodayPage 본문도 동일했다. 시작 가능 미리보기의 10개 요청을 전체 작업 조회라고 해석하지 않는다.

[작업 도메인 문서](https://github.com/Pinit-Scheduler/pinit-docs/blob/main/docs/design/task.md)와 TaskService도 확인했다. 시작 가능 목록과 회원 시간대의 마감 일자 목록은 별도 경로다. 이 시안에서는 기존 조건을 다시 정의하지 않는다.

승인받지 않은 중복 제거·오늘/미래/완료 재분류 및 그 검사 코드는 제거했다. 사용자의 모든 공간 요구는 소속 범위에 관한 요구로 반영하며, 기존 오늘 패널을 무제한 전체 작업 목록으로 바꾸는 정책은 확정하지 않는다. 별도로 만들었다가 삭제한 이전 시안도 이 변경에 포함하지 않는다.
