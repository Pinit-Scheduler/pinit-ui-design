# 새 작업·일정의 기본 소속

2026-11-10 · 디자인 시안 0.23.0 · `origin/main`(`d65d70d`)에서 `claude/create-defaults`로 분기. FE 구현은 `pinit-fe`의 `claude/create-defaults`(`b17f55d`)다.

## 출발점

- 사용자 요청(2026-11-10): 작업이나 일정을 만들 때 지금 열려 있는 스페이스·프로젝트가 있으면 그것을 기본값으로 둔다. 구현하면서 문제가 될 만한 부분은 애니메이션으로 덮는다. 이 시안 문서도 구현과 같게 갱신한다.
- 이전 시안(0.21.0까지)의 규칙: 작업 화면에서 연 새 작업만 선택 스페이스·프로젝트로 시작했다. 일정 화면에서 연 새 일정을 포함해 나머지는 모두 나의 스페이스였다(`purpose-spaces-crud.js`의 `openTaskFormV2`·`openScheduleFormV2`).
- FE(`pinit-fe@ce49af9`)의 이전 규칙: 스페이스는 선택 스페이스, 오늘의 작업 추가만 나의 스페이스였고, 프로젝트는 늘 "프로젝트 없음"이었다.
- 백엔드는 바꾸지 않는다. 생성 요청은 이미 스페이스와 프로젝트를 받고, 프로젝트가 그 스페이스 것이 아니면 거절한다(`pinit-monolith@f331a65`의 `SpaceCatalogService.validateProject`).

## 규칙 (FE와 같음)

폼을 연 순간 그 뒤에 보이던 화면으로 한 번 정한다. 이후 선택을 바꿔도 열린 폼은 그대로이고, 소속 한 줄의 "바꾸기"로 언제든 바꾼다.

| 폼을 연 화면 | 스페이스 | 프로젝트 |
| --- | --- | --- |
| 작업, 일정, 작업 맵, 하루 계획(FE), 반복 관리 | 선택 스페이스 | 선택 프로젝트. 완료한 프로젝트면 없음 |
| 오늘 | 나의 스페이스 | 없음 |
| 스페이스 허브, 통계, 설정 등 그 밖 | 선택 스페이스 | 없음 |

- 완료한 프로젝트를 기본값에서 빼는 것은 이 작업의 제안이다. 사용자가 고르면 그 프로젝트로도 만들 수 있다(선택 목록에는 그대로 있다).
- FE는 여기에 더해 삭제된 프로젝트, 다른 스페이스의 프로젝트, 아직 불러오지 않은 프로젝트도 기본값에서 뺀다. 이 시안의 예시 데이터에는 그런 상태가 없다.
- 이 시안에는 하루 계획 화면이 따로 없다.

## 모션

[모션 명세](motion.md)의 토큰을 그대로 쓴다.

1. **소속 한 줄의 값이 바뀔 때.** 표시 색과 "스페이스 › 프로젝트, 담당" 글자가 `--motion-base`(180ms) 동안 `--motion-ease`로 흐리게 들어온다. 불투명도만 바뀌므로 줄인 모션에서도 남고, 그때는 `--motion-fast`(120ms)다. 폼을 연 첫 값은 움직이지 않는다. 대화상자의 진입이 그 순간을 이미 덮는다.
2. **서버 기본 담당자를 기다리는 동안(FE).** 요약 줄은 "담당자 확인 중"으로 열리고, 응답이 오면 1번처럼 "담당 나"로 바뀐다. 전에는 요약 아래에 "서버의 소속·담당자 정보를 확인하고 있어요…" 줄이 따로 보였다가 응답 때 사라져 폼 전체가 한 줄 당겨 올라왔다. 이제 이 문장은 보조 기술에만 읽힌다(`role="status"` 유지). 이 시안은 담당자를 바로 알아 기다림이 없다.

## 시안 변경

- `purpose-spaces-crud.js`: `createAssignmentPurposeV23()`가 위 규칙으로 새 작업·일정의 소속을 정한다. 기존 항목·작업에서 만든 일정은 원래대로 그 항목의 소속을 쓴다.
- `motion.js`: `followupAffiliationRefreshV21`을 감싸 요약 글자가 실제로 바뀌었을 때만 표시 색과 글자에 `m-fade`를 건다.
- `motion.css`: `.affiliation-summary .m-fade`와 줄인 모션 규칙.
- `package.json` 0.23.0, `index.html`(빌드 결과), `README.md`, `CHANGELOG.md`, [모션 명세](motion.md)의 동작 6, 이 문서.

## 검증

실행한 것:

- `npm run check`, `npm run build` 통과.
- `npm start`(http://127.0.0.1:4173)를 Claude 데스크톱 앱 내장 브라우저에서 열고, 선택을 커리어 성장 › 면접 준비로 둔 채 화면마다 새 작업·새 일정 폼을 열어 요약 줄을 읽었다.
  - 작업·일정·작업 맵·반복 관리: 작업과 일정 모두 "커리어 성장 › 면접 준비, 담당 나".
  - 오늘: 둘 다 "나의 스페이스, 담당 나". 스페이스·통계: 둘 다 "커리어 성장, 담당 나".
  - 면접 준비를 완료로 둔 뒤 작업 화면: "커리어 성장, 담당 나". 확인 후 완료를 되돌렸다.
  - 폼을 열 때 `m-fade` 0개, 프로젝트를 "프로젝트 없음"으로 바꾸면 표시 색과 글자 두 요소에 `m-fade-in`, 끝난 뒤 클래스 0개.
  - 390×844 일정 화면에서 새 일정 폼의 요약 줄과 가로 스크롤 없음. 콘솔 오류 0건.
- FE에서 실행한 것은 [FE 문서](https://github.com/Pinit-Scheduler/pinit-fe/blob/claude/create-defaults/docs/purpose-spaces.md)의 "새 항목의 기본 소속" 절에 있다(로컬 mock API만, 운영 API 미사용).

확인하지 못한 것:

- 내장 브라우저가 줄인 모션 설정이라 시안의 전체 모션 경로(180ms)는 실행하지 않았다. 줄인 모션의 120ms 페이드만 `document.getAnimations()`로 확인했다. 프레임 단위 모양은 보지 못했다.
- 1365×900 캡처와 화면 캡처 파일은 남기지 않았다. 실제 기기, Safari, Firefox는 확인하지 않았다.
