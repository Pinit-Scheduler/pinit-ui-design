# 핀잇 목적 공간: CRUD 흐름과 PRD 커버리지

2026-11-08 · 디자인 시안 0.17.1 · 기존 pinit-ui-design 소스에 반영.

## 기준과 범위

기준은 [목적 기반 프로젝트·협업 공간 PRD 초안](https://github.com/Pinit-Scheduler/pinit-docs/blob/c3e37f329f615618c8f99189a574ed73aa64e853/docs/projects/purpose-project-spaces/README.md)이다. 오케스트레이션 채팅에 확인한 결과, 더 최신 PRD나 삭제·권한·일정 공유에 대한 후속 확정은 없다. 확정 요구 R-01~R-14를 시안에 연결하고, Q-01~Q-15의 상태를 별도로 남긴다.

이번 대화의 추가 결정은 개인 작업 우선, 오늘에서 모든 공간의 내 작업 보기, 반응형과 향후 앱 사용 고려, 기존 디자인 소스에서 수정하고 검증·커밋·푸시 기록을 남기는 것이다. 같은 작업이 오늘 마감과 시작 가능에 모두 해당할 수 있으므로 두 구역의 교집합을 제거하지 않는다. 관련 지식베이스·실제 FE/BE 대조 근거는 [이전 증적](purpose-spaces.md)에 있다.

이 저장소는 브라우저 예시 데이터로 실행하는 디자인 문서다. 아래의 '연결'은 화면과 예시 상태 전이를 뜻한다. 실제 인증·메일·서버 권한·복수 계정 실시간 협업을 구현하거나 검증한 결과가 아니다.

## 디자인 계획과 검토

기존 브랜드의 배경 #F4F6FA, 표면 #FFFFFF, 본문 #202A3C, 보조 글자 #727C8D, 파랑 #345CE5, 선택 배경 #EDF2FF와 Noto Sans KR을 유지한다. 이름·목적·기여할 성과를 왼쪽 정렬하고, 관리 화면의 목적·정보 / 프로젝트 / 참여자로 진입점을 묶는다. 새로운 대시보드나 독립 시안을 만들지 않는다.

데스크톱은 공간 버튼 아래 선택 패널과 최대 660px 관리 대화상자, 모바일은 공간 선택 하단 시트와 한 열 관리 폼을 사용한다. 헤더와 주요 동작은 유지하고 내용만 스크롤한다. 선택·수정·삭제의 영향 범위와 취소 동작이 시각 장식보다 우선한다. 모바일에서 참여자 행을 짧게 정리하고, 터치 영역·줄바꿈·키보드 포커스를 확인했다. 최종 320px 캡처에서 관리 탭이 두 줄로 나뉘는 점을 발견해 세 탭을 같은 폭의 한 줄로 정돈하고 44px 터치 높이를 유지했다.

초기 시안의 누락은 탐색 이후 생성·편집·삭제·참여자 관리로 이어지는 경로였다. 기존 작업·일정 폼에 소속 필드를 붙이고, 목적·프로젝트·참여자 관리를 같은 공간 맥락에 연결하는 방향으로 보완했다.

## 화면 진입과 CRUD

| 대상 | 생성 | 조회 | 수정 | 삭제·종료와 복원 |
| --- | --- | --- | --- | --- |
| 공간 | 공간 전환 → 목적 공간 만들기 | 공간 선택, 공간 관리 | 목적·정보 → 이름 수정 | 공간 삭제 → 영향 확인 → 항목 처리 → 휴지통 → 복원 |
| 목적 | 공간 만들기의 목적 또는 공간 관리 → 목적 작성 | 공간 관리, 프로젝트 맥락, 작업 상세 | 목적 수정 | 목적 내용 삭제. 공간과 하위 항목을 남기는 검토안 |
| 프로젝트 | 사이드바·모바일 프로젝트 탭·공간 관리 → 프로젝트 만들기 | 공간별 목록 → 프로젝트 작업 | 이름·기여할 성과 수정 | 완료·재개, 삭제 영향 확인, 휴지통 복원 |
| 참여자 | 사람 초대 → 초대 화면 → 참여 | 참여자·대기 초대 목록 | 공유 내용 편집, 작업 담당자 선택 | 초대 거절·취소, 참여자 제외, 공간 나가기, 마지막 참여자 안내 |
| 작업 | 기존 작업 추가 + 소속 자동 선택 | 오늘·공간·프로젝트·기존 작업 상세 | 기존 폼 + 소속·담당자 변경 | 기존 삭제·휴지통 경로 유지. 소속 삭제 시 처리·복원 경로 연결 |
| 일정 | 기존 일정 추가·작업 배정 + 소속 | 기존 달력·상세에 소속과 보기 범위 | 기존 폼 + 소속·보기 범위 | 기존 삭제·휴지통 유지. 상위 공간·프로젝트 삭제 영향에 포함 |

오늘에서 새로 기록할 때는 기본 개인 공간, 공간/프로젝트의 작업 화면에서는 현재 맥락을 기본값으로 사용한다. 소속은 폼에서 바꿀 수 있다. 공간에 직접 기록하거나 추가 공간의 목적을 비워 두는 방식은 Q-05에 대한 검토안이다.

| R-07 | 작업·일정 편집 → 공간·프로젝트 변경 | 기존 작업 공유 이동 및 일정 소속 저장 확인. 연결 일정 동반 이동은 명시적 선택인 검토안 |
| R-08 | 프로젝트 완료·재개 | 상태를 바꿔도 하위 작업의 완료 상태가 유지되는 것을 확인 |

| R-10 | 공유 공간의 목적 작성·수정 | 동일 목적 편집 경로 제공. 다중 계정 동시 편집은 구현하지 않음 |
| R-11 | 공유 공간의 목적·프로젝트·작업·일정 편집 | 참여자에게 같은 내용 편집 진입 제공. 삭제·참여자 관리 권한은 검토안으로 구분 |
| R-12 | 하나의 작업 데이터와 완료 상태 | 멤버 초대/담당자 변경 시 작업을 복제하지 않음. 예시 모델과 화면에서 확인; 실제 다중 세션 동기화는 범위 밖 |
| R-13 | 공유 작업 폼의 담당자 한 명 | 담당자 변경, 제외 시 재배정, 오늘의 내 작업 반영 확인. 담당자 미정 허용은 여전히 미결 |
| R-14 | 공유 이동 안내·확인, 상세 활동 기록 | 미확인 저장 차단과 이동 전 예시 기록/이동 기록의 보존·표시 확인. 기록 유형별 권한은 Q-10 미결 |

## 미결 질문과 시안의 제안

'미결'은 범위 제외를 뜻하지 않는다. 관련 화면을 제안으로 만들었으며, 제품 정책 확정이나 서버 구현으로 보고하지 않는다. 담당자 미정만 질문 후 미결이고, 나머지는 PRD에서 미질문으로 기록된 상태를 유지한다.

| ID | 시안에 제시한 처리 | 남아 있는 결정 |
| --- | --- | --- |
| Q-01 담당자 미정 | 기본 담당자 나, 한 명 선택 | 미정 허용 여부. 필수 지정을 사용자 결정으로 확정하지 않음 |
| Q-02 일정 소유·실행 | 개인/공간 보기 범위 선택과 소속 표시 | 소유자, 공용 실행 상태, 작업당 연결 수. 실제 API 제약 변경 없음 |
| Q-03 담당자 변경 | 한 명 선택, 제외·탈퇴 시 재배정 | 변경 권한과 진행 중 실행·기존 일정 처리 |
| Q-04 이동 단위 | 작업·일정 개별 이동, 연결 일정 동반 이동 체크, 삭제 시 하위 항목 보관/휴지통 선택 | 프로젝트 통째 이동, 공간을 넘는 선후 관계, 실행 중 충돌. 선택하지 않은 연결 일정은 현재 소속에 유지 |
| Q-05 공간·프로젝트 관계 | 프로젝트 없음 허용, 추가 공간의 목적 생략 허용 | 두 허용 방식을 제품 정책으로 확정할지 |
| Q-06 기존 카테고리 | 기존 분류를 유지하며 공간·프로젝트를 별도로 표시 | 대체 여부, 분류 공유와 데이터 이전 |
| Q-07 완료·재개·보관 | 프로젝트 수동 완료·재개, 하위 작업 상태 보존 | 자동 완료, 목적 달성, 프로젝트 보관과 완료 후 추가 규칙 |
| Q-08 참여자·공간 수명주기 | 초대/참여/거절/취소/제외/탈퇴, 마지막 참여자 안내 | 역할별 권한·마지막 참여자 처리 확정. 별도 관리자 역할을 확정하지 않음 |
| Q-09 삭제·복구 | 영향 수 표시, 소속 이동 또는 함께 휴지통, 원래 구조 복원, 부모 먼저 복원 | 삭제·복구 권한, 보관 기간, 위치/담당자 충돌. 기존 작업·일정 보관 정책을 새 공간에 자동 적용하지 않음 |
| Q-10 기록 공유 | 공유 이동 전 확인, 이동 전 예시 기록과 변경 기록 유지 | 실행/삭제/복구별 범위, 개인으로 되돌린 후 접근. 실제 로그와 권한 시스템은 미구현 |
| Q-11 조회·계획·통계 | 사용자가 결정한 오늘의 모든 공간 내 작업 통합 보기 반영 | 공유 일정·계획·통계 집계 정책. 기존 달력·통계 기준은 임의로 재정의하지 않음 |
| Q-12 동시 수정 | 같은 예시 객체를 편집하는 경로 | 실시간 갱신·충돌·알림 UI와 서버 정책은 아직 미설계/미검증 |
| Q-13 기존 기능 연결 | 기존 반복·순서·계획·휴지통·통계 진입 유지 | 각 기능의 공유 권한과 공간 범위. 기존 조건을 일괄 치환하지 않음 |
| Q-14 팀의 범위 | 현재 공간 참여자 목록으로 협업 구성 | 여러 공간에서 재사용할 별도 팀 엔티티는 미결이며 추가하지 않음 |
| Q-15 전달·평가 | 확정 요구와 CRUD를 기존 디자인 저장소의 반응형 예시 흐름으로 연결 | 제품 구현 우선순위·출시 범위·사용성 평가 기준은 별도 결정 |

## 실제 브라우저 검증

Chrome에서 기존 index.html을 로컬 HTTP로 실행했다. 아래는 예시 데이터로 직접 실행한 범위다.

| 검증 | 실제 관찰 |
| --- | --- |
| 공간 생성·수정 | 빈 이름 오류, 목적과 함께 생성, 이름·목적 수정, 빈 공간 생성·삭제 |
| 목적 편집 | 수정 저장, 내용 삭제 전 취소, 내용 삭제 후 재작성, Escape 취소 |
| 프로젝트 | 생성 → 작업 추가 → 이름/성과 편집, 완료 → 재개 시 하위 상태 보존 |
| 참여자 | 초대 → 참여, 같은 이메일 중복 오류, 거절, 대기 초대 취소 |
| 제외·탈퇴 | 담당 작업 1개를 남은 사람에게 재배정, 마지막 참여자 안내, 다른 참여자가 있을 때 탈퇴 후 오늘에서 해당 담당 작업 제외 |
| 소속·기록 | 기존 작업을 공유 공간으로 이동할 때 확인 누락 오류, 확인 후 이동·활동 기록 표시, 동반 이동 미선택 시 연결 일정의 기존 위치 유지 |
| 일정 | 작업에서 일정 배정, 공유 보기 범위 저장, 제목 수정, 상세의 소속·범위·기록 확인 |
| 삭제·복원 | 처리 방법 미선택 오류, 이동 영향 미확인 오류, 다른 소속에 보관 후 프로젝트 구조만 복원, 공간과 작업 함께 휴지통 이동 후 새로고침·일괄 복원 |
| 복원 순서 | 부모가 삭제된 작업부터 복원하면 소속 먼저 복원하도록 안내하고, 소속과 작업 함께 복원 |
| 실행 중 보호 | 진행 중 일정이 있는 공간 삭제 진입 시 일정 완료/취소 안내 |
| 기존 오늘 | 예시 초기화 후 작업 5개, 오늘 마감 3개/시작 가능 3개 유지. 교집합 항목을 양쪽에서 보존 |
| 반응형 | CSS 1365×900, 400×844, 320×740. 320px 목적 관리 대화상자 x=12, 폭=296, 가로 넘침 없음, 고정 동작 하단이 화면 안에 있음 |
| 키보드·닫기 | 취소/Escape 후 폼 닫힘과 body 스크롤 복구. 데스크톱에서 열고 모바일로 바꾼 뒤 닫아도 보이는 공간 버튼으로 포커스 복귀 |
| 최종 오류 로그 | 마지막 새로고침·관리 화면 진입 후 브라우저 오류 로그 없음. 초기 연결 중 발견한 초기화 순서 오류는 준비 상태 가드로 수정 |

npm run check(기존 그래프·행렬·통계·개요 회귀 검사와 전체 소스 구문 검사), npm run build를 실행했다. 별도 패키지 설치 없이 기존 빌드 경로를 유지한다.

저장 실패 시 관리 입력을 보존하고 모델을 되돌리는 경로를 추가했지만, 브라우저 저장 용량을 강제로 고갈시키는 실험은 하지 않았다. 실제 로그인한 두 사용자 간 권한·공동 상태 전파, 이메일 전송, 실제 모바일 기기의 키보드·안전 영역, 서버 지연·충돌은 검증하지 않았다.

## 변경 파일과 반영

purpose-spaces-crud.js/css는 기존 화면을 확장하는 관리/소속 모듈이다. refinement.js는 오늘의 기존 마감·시작 가능 조건을 보존하면서 예시 담당자 범위만 입력받는다. build.cjs와 package.json에 새 소스를 등록하고 index.html을 재생성했다. README와 CHANGELOG에 흐름 및 검증 범위를 갱신했다. 작업 브랜치에 일관된 커밋으로 반영하며, 기본 브랜치 병합·제품 코드 변경·배포는 수행하지 않는다.
